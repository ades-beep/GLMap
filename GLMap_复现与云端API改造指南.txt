0. 结论速览（TL;DR）
================================================================================

【项目是什么】
CVPR 2026 Highlight 论文《Multi-Scale Gaussian-Language Map for Zero-shot Embodied
Navigation and Reasoning》的官方核心代码。在 Habitat 仿真环境里，让 agent 边走边把
RGB-D 观测建成一张"3D 高斯 + 语言"的多尺度语义地图（GLMap），支持零样本具身导航与推理。

【架构一句话】
Habitat 仿真 → (RGB-D) → MLLM 开放词汇物体/群组提议 → VLM(GroundingDINO/YOLOv7) 检测
→ MobileSAM 分割 → 深度反投影出彩色点云 → 逐实例高斯参数估计（3DGS）→ 实例/群组管理器
+ 空间索引 → 跨帧融合（几何+文本）→ 序列化(pkl) / PLY 导出 / 渲染。

【复现难度定位】
- 工程量中等偏大：4 个 GitHub 子模块 + Habitat 全家桶 + 5 个神经网络权重 + HM3D 数据集。
- 中国大陆有 4 个必须开代理的卡点：4 个子模块 clone、mobile-sam 的 git+https 安装、
  VLM 权重的 GitHub Releases 下载、BLIP2 的 HuggingFace 权重下载。
- 数据集 HM3D 需要**申请授权**（学术邮箱 + 数天审批），这是最不可控的一步。

【你的 3060 12GB 能用吗？】
能用，而且比你预想的乐观。真正跑不动的是 MLLM 里的 gemma3:27b（README 明说需 ≥24GB）。
但项目里**已经内置了 OpenAI 兼容的云端 MLLM 接口** src/mllm/openai_mllm.py，默认就指向
阿里云百炼(DashScope)，所以"改成云端 API"几乎只是**接线工作（改 3 个文件、约 10 行）**，
不需要从零写接口。所有 VLM（GroundingDINO/MobileSAM/YOLOv7）本地显存占用很小，
完全可以留在 3060 上跑。详见第 4 节。

1.1 论文与定位
--------------------------------------------------------------------------------
- 标题：Multi-Scale Gaussian-Language Map for Zero-shot Embodied Navigation and Reasoning
- 会议：CVPR 2026，Highlight，页码 37086-37097
- 作者：Sixian Zhang, Yiyao Wang, Xinhang Song, Keming Zhang, Zijian Xu, Shuqiang Jiang
- 核心思想：把场景表示成"多尺度"结构 —— 底层是**实例(instance)**级 3D 高斯，
  上层是**群组(group)**级（功能上协同/交互的物体集合，如"桌子+椅子=休息娱乐区"），
  两层都挂语言描述，从而实现零样本的开放词汇导航与推理。

1.3 数据流：一次 update_gl_map() 的完整链路
--------------------------------------------------------------------------------
对应 src/glmap/api.py，这是理解全项目的关键函数，按顺序做 9 件事：

  (1) 读观测：rgb / depth / gps / compass
  (2) 坐标变换：Habitat 的 xRyUzB → 项目内部的 xFyLzU，相机高度固定 +0.88m
  (3) 【调 MLLM】mllm.grounding(image) —— 抽帧下采样 2 倍后送多模态大模型，
      要求返回 {scene_summary, objects[{instance_id, category, description}],
      groups[{instances[], description}]}。即"开放词汇的物体与群组提议"。
      结果落盘 outputs/{scene}_{ep}/ {step}/mllm_result.json
  (4) 类别去重（每类只保留一个），得到 categories 列表
  (5) 【调 VLM】detect_objects()：类别分流 —— COCO 类走 YOLOv7，自定义类走
      GroundingDINO；再用 MobileSAM 按 bbox 分割出 mask。可视化落盘 segmented_img.png
  (6) 掩码过滤：去空 mask、同类别只保留分数最高的、再按点云非空过滤
  (7) 【调 3DGS 估计器】get_habitat_object_point_clouds() 深度反投影出带色点云，
      GaussianEstimator.estimate() 逐实例估出高斯参数(means/scale/rot/opacity/SH)
  (8) 【写地图】add_instance_from_property() 建实例；mllm_result.groups 经 local_id
      → global_id 映射后 add_group_from_property() 建群组
  (9) 释放显存 torch.cuda.empty_cache()

另外两条"隐式"的 MLLM 调用路径（容易漏看，改造时必须一起改）：
  - src/glmap/core/instance_manager.py:84 → fusion/merge_instance.py:renew_instance_description()
    实例描述历史不一致时，调 MLLM 重新归纳 category/description
  - src/glmap/core/group_manager.py:123 → fusion/merge_group.py:generate_group_description()
    每 GROUP_MERGE_INTERVAL(=3) 步，调 MLLM 生成群组描述
  - fusion 里还用 embed_text 做文本相似度（nomic-embed-text），阈值 0.7

1.4 依赖的三类外部模型（决定改造边界）
--------------------------------------------------------------------------------
  A. MLLM（多模态大模型）——"大脑"，做开放词汇提议与语义归纳
     默认 Ollama 本地：gemma3:27b（grounding，需 ≥24GB 显存）
                       qwen3:8b（合并/描述，注意是**纯文本**任务）
                       nomic-embed-text（文本嵌入）
     ★ 这是 3060 12GB 唯一跑不动、也是唯一需要换成云端 API 的部分。

  B. VLM（视觉模型）——"眼睛"，检测与分割，全部本地、显存友好
     GroundingDINO(SwinT, ~700MB) / MobileSAM(~40MB) / YOLOv7-e6e(~290MB)
     / BLIP2-ITM（默认路径未被 get_object_utils 直接调用，属可选）
     ★ 建议保留本地，无需改造。

  C. 3D 高斯光栅化 —— diff_gaussian_rasterization 的 CUDA 扩展（需编译，依赖 nvcc）

步骤 2：四个子模块（★ 最大的坑）
--------------------------------------------------------------------------------
README 写的是：
    git submodule update --init --recursive
    pip install third_party/diff-gaussian-rasterization

【本机必然失败】因为本目录没有 .git 和 .gitmodules（你拿到的是源码快照，
不是 clone 下来的仓库）。所以这一步必须**手工 clone 四个仓库**：

    cd third_party
    git clone https://github.com/graphdeco-inria/diff-gaussian-rasterization.git
    git clone https://github.com/IDEA-Research/GroundingDINO.git
    git clone https://github.com/WongKinYiu/yolov7.git
    git clone https://github.com/facebookresearch/habitat-lab.git
    cd habitat-lab && git checkout tags/v0.3.1 && cd ..   # README 要求 v0.3.1

    cd ..   # 回到项目根
    pip install third_party/diff-gaussian-rasterization

[注意1] README 没给出这四个仓库的具体 URL（因为 .gitmodules 丢了）。
        diff-gaussian-rasterization 的**具体 fork 无法从快照确定** —— 源码里只
        `from diff_gaussian_rasterization import GaussianRasterizer`，这是原始
        graphdeco-inria 版本的模块名与类名，所以先用官方仓库试；
        若源码用到官方版没有的参数（如 scale_modifier 之外的自定义项）导致
        import 或调用报错，再去作者主页找 CVPR 2026 配套的 fork。
[注意2] diff-gaussian-rasterization 需要能编译 CUDA 扩展（nvcc + torch 版本匹配）。
        编译失败时：demo 默认会落 PLY 文件，可以丢到
        <https://superspl.at/editor> 在线查看高斯结果（README 明确给了这个兜底方案）。
[注意3] YOLOv7 在本项目里同时被两处用到：third_party/yolov7（权重/结构）和
        src/vlm/detector/yolov7.py（服务封装）。检测权重由步骤 6 的 wget 提供。

步骤 6：VLM（权重下载 + 起服务）
--------------------------------------------------------------------------------
6.1 下载权重（README 原文，注意需要先建 data/ 目录）

    mkdir -p data
    # mobile sam
    wget -O data/mobile_sam.pt \
      https://github.com/ChaoningZhang/MobileSAM/raw/master/weights/mobile_sam.pt
    # groundingdino
    wget -O data/groundingdino_swint_ogc.pth \
      https://github.com/IDEA-Research/GroundingDINO/releases/download/v0.1.0-alpha/groundingdino_swint_ogc.pth
    # yolov7
    wget -O data/yolov7-e6e.pt \
      https://github.com/WongKinYiu/yolov7/releases/download/v0.1/yolov7-e6e.pt

    【★ 全部是 github.com / GitHub Releases，中国大陆必须开代理】

    另外 GroundingDINO 的 pip 安装（README 指向其 Install Guide）：
        pip install -e third_party/GroundingDINO

6.2 启动 VLM 服务（README 推荐以 HTTP 服务方式常驻，避免每次启动重载模型）

    # 在项目根目录执行；如果报 ModuleNotFoundError: vlm，先：
    export PYTHONPATH=$PWD/src

    python -m src.vlm.detector.grounding_dino --port 12181
    python -m src.vlm.itm.blip2itm          --port 12182
    python -m src.vlm.segmentor.sam         --port 12183
    python -m src.vlm.detector.yolov7       --port 12184

    默认就是 HTTP 模式（src/vlm/config.py 里 DEFAULT_HTTP_MODE="true"）。
    改成进程内本地模式（省去起服务，但每次启动都要重载模型）：
        export VLM_GROUNDING_DINO_HTTP_MODE=false
        export VLM_MOBILE_SAM_HTTP_MODE=false
        export VLM_BLIP2ITM_HTTP_MODE=false
        export VLM_YOLOV7_HTTP_MODE=false

    【BLIP2 特别注意】blip2itm.py 会 `from lavis.models import
    load_model_and_preprocess` 并在首次加载时**从 HuggingFace 拉权重**。
    HuggingFace 在中国大陆被墙 —— 这一步必须开代理，或设镜像：
        export HF_ENDPOINT=https://hf-mirror.com
    （demo 主链路其实不直接调 BLIP2，但你把 12182 服务起起来就会触发下载）

6.3 端口与显存
    12181 GroundingDINO / 12182 BLIP2-ITM / 12183 MobileSAM / 12184 YOLOv7
    端口可用环境变量覆盖：VLM_GROUNDING_DINO_PORT 等（见 src/vlm/config.py）
    显存合计约 1~1.5GB，3060 12GB 毫无压力。

4. 云端 API 改造方案（面向 RTX 3060 12GB）
================================================================================

4.1 先明确边界：什么该上云，什么该留本地
--------------------------------------------------------------------------------
  上云：只有 MLLM。理由——gemma3:27b 需要 24GB 显存（README 原文），3060 只有 12GB；
        而 MLLM 是纯 API 调用式的"大脑"，改成 HTTP 调用不影响任何 3D 逻辑。
  留本地：全部 VLM（GroundingDINO ~700MB + MobileSAM ~40MB + YOLOv7-e6e ~290MB
        + BLIP2 可选 ≈ 1~1.5GB 显存）和 3DGS 估计/光栅化（点云规模小，3060 够用）。
        这些换成 API 反而要传图/传点云，得不偿失，且没有现成接口。

4.2 好消息：云端接口已经写好了，不用从零开发
--------------------------------------------------------------------------------
项目里已经存在 src/mllm/openai_mllm.py，而且是**正规实现**：

  class OpenAIMLLM(MLLM_Mixin):
      def __init__(self, model_id="qwen3-vl-plus",
                   api_key=None,
                   base_url="https://dashscope.aliyuncs.com/compatible-mode/v1")

  · 继承 MLLM_Mixin → 直接拥有 grounding() / compare_instance_similarity() /
    merge_instance_descriptions() / renew_instance_description() /
    generate_group_description() / instance_target_value() / group_target_value()
    这些高层方法，即**接口完全兼容**，可直接替换 OllamaMLLM。
  · 已实现 chat()（单图）与 chat_images()（文图交替多图），图片用
    image_to_base64_data_uri() 转 data-uri，符合 OpenAI/GPT-4V 与 DashScope 规范。
  · 已实现 embed_text()，默认 model_id="text-embedding-v3"（DashScope）。
  · API key 读取顺序：构造参数 → 环境变量 OPENAI_API_KEY → DASHSCOPE_API_KEY。
  · 缺 key 时不抛异常，而是 client=None 进入 mock 模式（chat 返回空串），
    表现为"地图建不出来"而不报错 —— 调试时注意从日志里认这个警告。
  · openai 包**已经在 environment.yml 里**（第 52 行），无需新增依赖。

4.3 需要动手的地方：3 个文件（约 10 行）
--------------------------------------------------------------------------------
当前代码里 OllamaMLLM 被**硬编码**在 3 处，这就是全部改造点：

  (A) src/glmap/glmap.py
      第 17 行：from mllm.ollama_mllm import OllamaMLLM
      第 60 行：self.mllm = OllamaMLLM(model_id=MLLMConfig.MODEL_ID)
                ↑ 这是 grounding 用的多模态模型，即 gemma3:27b 那一处

  (B) src/glmap/fusion/merge_instance.py
      第 7 行：from mllm.ollama_mllm import OllamaMLLM
      第 17-22 行：_get_mllm() 里 OllamaMLLM(model_id=InstanceFusionConfig.MERGE_RESULT_LLM_MODEL_ID)
                  ↑ 模块级单例，用于实例描述归纳 + embed_text 算相似度

  (C) src/glmap/fusion/merge_group.py
      第 7 行：from mllm.ollama_mllm import OllamaMLLM
      第 17-22 行：_get_mllm() 里 OllamaMLLM(model_id=GroupFusionConfig.MERGE_DESCRIPTION_MODEL_ID)
                  ↑ 模块级单例，用于群组描述生成 + embed_text

【推荐改法：加一个统一工厂，三处都调它（避免重复判断逻辑）】
  新建 src/mllm/factory.py（约 15 行）：

      import os
      from .ollama_mllm import OllamaMLLM
      from .openai_mllm import OpenAIMLLM

      def build_mllm(model_id: str):
          backend = os.getenv("GLMAP_MLLM_BACKEND", "openai").lower()
          if backend == "openai":
              return OpenAIMLLM(
                  model_id=model_id,
                  api_key=os.getenv("DASHSCOPE_API_KEY"),
                  base_url=os.getenv(
                      "GLMAP_MLLM_BASE_URL",
                      "https://dashscope.aliyuncs.com/compatible-mode/v1",
                  ),
              )
          return OllamaMLLM(model_id=model_id)

      # 在 src/mllm/__init__.py 里一并导出

  然后三处改为：
      from mllm.factory import build_mllm          # 替换原来的 ollama_mllm import
      self.mllm = build_mllm(MLLMConfig.MODEL_ID)  # 替换原来的 OllamaMLLM(...)

  【为什么不用环境变量直接改 OllamaMLLM】Ollama 官方 python 客户端只能连
  OLLAMA_HOST（本地/自建 ollama 服务），**不是 OpenAI 兼容协议**，无法直接指向
  百炼/OpenAI，所以必须换成 OpenAIMLLM 这条路。

4.4 配置项改动（src/glmap/config.py）
--------------------------------------------------------------------------------
该文件里的模型 ID 全是 Ollama 的模型名，换成云端后必须全部改掉，否则调用会失败：

  原值（Ollama 模型名）                    云端应改为（示例）
  ─────────────────────────────────────── ─────────────────────────────────────
  MLLMConfig.MODEL_ID = "gemma3:27b"      → "qwen3-vl-plus"（★ 必须是**视觉**模型！）
  InstanceFusionConfig.MERGE_RESULT_LLM_MODEL_ID = "qwen3:8b"   → "qwen-plus"
  GroupFusionConfig.MERGE_DESCRIPTION_MODEL_ID  = "qwen3:8b"   → "qwen-plus"
  InstanceFusionConfig.TEXT_EMBEDDING_MODEL_ID  = "nomic-embed-text"
                                          → "text-embedding-v3"
  GroupFusionConfig.TEXT_EMBEDDING_MODEL_ID     = "nomic-embed-text"
                                          → "text-embedding-v3"

【★ 最容易踩的坑】嵌入模型必须改。原因：merge_instance.py:34-35 与
merge_group.py:28 是这样调的——
      emb = _get_mllm().embed_text(text, model)     # model 来自上面那两个配置
而 OpenAIMLLM.embed_text 的签名是 embed_text(self, text, model_id="text-embedding-v3")，
第二个位置参数就是 model_id。若仍传 "nomic-embed-text"，DashScope 会报模型不存在，
函数内部 catch 后**返回空 list**，上层 get_text_embedding_similarity 直接
raise ValueError("Embedding failed...")，表现为建图过程中途崩溃。

    DASHSCOPE_API_KEY=sk-xxxxxxxxxxxxxxxx
    # 可选：切到别的 OpenAI 兼容服务商

4.7 两条落地路线（按你的偏好选一条）
--------------------------------------------------------------------------------
【路线 A：全云（最简单，改动最少，强烈推荐先做这个）】
  · MLLM grounding + 文本 LLM + 嵌入 全部走 DashScope。
  · 改动 = 4.3 的 3 个文件 + 4.4 的 5 个配置值 + 一个 .env。
  · 3060 只需承担 VLM(1~1.5G) + 3DGS，显存非常宽裕。
  · 优点：不用装 Ollama、不用管本地模型显存、省心。
  · 代价：每步建图一次网络往返，有 API 费用（grounding 是每步一次，最多 500 步；
          建议先用 --preset 的 ~12 步调试，别一上来就手动走 500 步）。

【路线 B：混合（省 API 费，稍微麻烦）】
  · grounding（gemma3:27b，跑不动）→ 云端 qwen3-vl-plus。
  · 文本 LLM（qwen3:8b）+ 嵌入（nomic-embed-text）→ **留在本地 Ollama**，
    3060 12GB 跑这两个绰绰有余（8B 量化后约 5~6GB）。
  · 做法：build_mllm() 只替换 glmap.py:60 那一处（grounding），
          merge_instance.py / merge_group.py 继续用 OllamaMLLM 且保持原配置不动。
  · 优点：占大头的频繁文本调用不花钱；缺点：要同时维护 Ollama 和云端两套。

  【建议】先用路线 A 打通全流程（排错面小），确认效果后再按需切路线 B。

4.8 其他注意事项
--------------------------------------------------------------------------------
  (1) 输出解析对格式敏感：src/mllm/parsers/parser.py 用
      `ast.literal_eval` 解析模型返回的 dict，**要求是 Python 字面量语法**
      （True/False/None），如果云端模型返回 JSON 风格的 true/false 会解析失败。
      prompts.py 里给的示例已经是 True/False（Python 风格），一般没问题；
      但换模型后如果发现大量 "Postprocessing failed" 日志（MLLM_Mixin
      有 3 次重试，失败最终返回 {}），第一件事就是去 outputs/{scene}_{ep}/
      {step}/mllm_result.json 看原文。必要时在提示词里补一句
      "Output must use Python literals True/False, not JSON true/false"。
  (2) grounding 会先把图**下采样 2 倍**（MLLM_Mixin.grounding 的
      downsample_step=2，640x480 → 320x240），这对云端 API 是好事，能省 token。
  (3) 费用与限流：chat_with_postprocessing 自带 3 次重试；如果遇到限流
      (429)，可以适当加 sleep 或换更高配额的模型。
  (4) 无 API key 时不会报错，只会静默走 mock（chat 返回 ""），
      表现为日志刷 "MLLM returned empty result." → 遇到这个先查 .env。
  (5) 切云端后**不再需要** 步骤 5 的 ollama pull gemma3:27b（路线 A 下连 Ollama
      整个都可以不装）。
  (6) config/ 下那三个 yaml 里的 `llm:` 段（llm_client: ollama / deepseek）
      是遗留字段，当前代码不读它，**不要被它误导**去改 yaml，模型 ID 请改
      src/glmap/config.py 的 dataclass。
